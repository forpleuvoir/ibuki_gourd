# 01 接入与依赖

这章解决：**怎么把 IbukiGourd 加进你的项目，并让你的代码被它接管**。

## 1. 仓库与依赖

```kts
repositories {
    maven("https://maven.forpleuvoir.moe/releases")
    maven("https://maven.forpleuvoir.moe/snapshots")
}

dependencies {
    implementation("moe.forpleuvoir:ibukigourd-fabric-26.2:0.11.1+alpha")   // Fabric
    implementation("moe.forpleuvoir:ibukigourd-neoforge-26.2:0.11.1+alpha") // NeoForge
    implementation("moe.forpleuvoir:ibukigourd-common-26.2:0.11.1+alpha")   // 纯逻辑 / 服务端
}
```

坐标规则：`moe.forpleuvoir:ibukigourd-<platform>-<minecraftVersion>:<version>`，
`platform` ∈ `common` / `fabric` / `neoforge`。

- 两个加载器都用普通 `implementation`：当前 Loom / ModDevGradle 下 Minecraft 已不再混淆，没有 remap 环节，
  旧的 `modImplementation` 已不存在；构件里的 mixin 配置与 access widener（`ibukigourd.classtweaker`）由加载器正常读取。
- **NeoForge** 用 `implementation`（构件自带 mixin 配置）。
- 依赖的 `nebula` / `compose-minecraft` / `reorderable` / `aseprite` 已内嵌进加载器构件
  （Fabric 走 `include`、NeoForge 走 `jarJar`），**不需要你声明**。
- 运行时前置：Fabric 侧需要 Fabric API 与 Fabric Language Kotlin；NeoForge 侧需要 Kotlin for Forge。

## 2. 把代码注册给 IbukiGourd

有三种方式，按"你的代码什么时候该被跑"选：

### 2.1 在自己的模组入口里调用（最常用）

配置管理器注册给处理器后，加载 / 保存 / 开屏都由它接管：

```kotlin
object YourModConfigs : ClientModConfigManager("your_mod_id", "config") { /* ... */ }

// 你的 ModInitializer / @Mod 类里
ClientModConfigHandler.register(YourModConfigs)
```

服务端配置同理：`ServerModConfigManager` + `ServerModConfigHandler.register(...)`。

### 2.2 通过 ServiceLoader 挂进 IbukiGourd 的初始化

`IbukiGourd.init()` 会遍历 `Services.INITS`（`java.util.ServiceLoader` 加载的 `ModInitialization`）。
在你的 `resources/META-INF/services/` 下建一个文件：

```
文件名：moe.forpleuvoir.ibukigourd.platform.services.ModInitialization
内容：
com.yourmod.YourInitialization
```

```kotlin
object YourInitialization : ModInitialization {
    override fun init() {
        ClientModConfigHandler.register(YourModConfigs)
    }
}
```

（仓库里 `common/src/devOnly/resources/META-INF/services/` 就是这么写的，可照抄。）

### 2.3 在多加载器环境里拿平台能力

```kotlin
import moe.forpleuvoir.ibukigourd.platform.PLATFORM
import moe.forpleuvoir.ibukigourd.platform.isDevEnv

if (PLATFORM.isModLoaded("modmenu")) { /* ... */ }
if (isDevEnv) { /* 仅开发环境 */ }
```

`PLATFORM` 是当前加载器的 `PlatformHelper` 实现（Fabric / NeoForge 各一份，经
`META-INF/services` 解析）；详细能力见 [11 多加载器与平台抽象](11-多加载器与平台抽象.md)。

## 3. 声明你的包路径（可选，但要跨模组扫描就需要）

`PlatformHelper.getIGModClasses()` 会读**模组元数据里声明的包名**，把它下面的类扫出来。
你自己的模组元数据里加一段：

```jsonc
// Fabric: fabric.mod.json
"custom": {
  "ibukigourd": { "package": "com.yourmod" }
}
```

```toml
# NeoForge: META-INF/neoforge.mods.toml
[modproperties."your_mod_id"]
package = "com.yourmod"
```

然后就能用 `scanModPackage { ... }` 过滤出自己的类（例如按接口或注解筛出你的注册项）：

```kotlin
val mine = scanModPackage { klass -> klass.isSubclassOf(MyRegistry::class) }
```

> 这个机制本身不注册任何东西，它是"给你自己用的发现入口"（`util/PackScanner.kt`）。

## 4. 代码该放哪

- 纯逻辑（配置、指令、事件、文本、工具）放 **common**，两端共用；
- 平台相关的读写走 `PlatformHelper`，**不要在 common 里判断加载器**；
- 客户端界面放 common 即可（屏幕只在客户端加载的类里用），mixin 放
  `common/src/main/java/.../mixin`，并在 `*.mixins.json` 里登记。
- 依赖 compose-minecraft：本仓在 common 用 `compileOnly`，加载器侧 `api + include|jarJar`；
  你若直接用到 CMP 的类（例如写屏幕），按同样的方式在你自己项目里声明。

## 5. 相关源码

- 入口：`IbukiGourd.init()` / `IbukiGourdClient.init()`
- 服务：`platform/Services.kt`、`platform/services/{PlatformHelper,ModInitialization}.kt`
- 配置处理器：`config/{Client,Server}ModConfigHandler.kt`
- 类扫描：`util/PackScanner.kt`
