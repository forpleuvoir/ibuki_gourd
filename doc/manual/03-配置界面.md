# 03 配置界面

这章解决：**把配置管理器变成界面**，以及**怎么改某个配置项的呈现方式**。

## 1. 最小用法

```kotlin
SokitsuScreen.open {                    // 主题 + 分辨率缩放（见 08 章）
    ConfigManagerWrapper(YourModConfigs)
}
```

`ConfigManagerWrapper` 自带：左列分组导航（列宽贴合最宽的分组名，由 `groupListMinWidth` / `groupListMaxWidth`
夹住）、右列顶部**常驻搜索框**（输入即过滤，关键词非空时内容区换成跨分组结果）、页内页签行（"这一页的直属配置项"
一签 + 其后每个直属子分组各一签，只有一签时不画）、每一行"名称 + 控件 + 重置 + tooltip"，以及各类型的编辑弹窗
（列表 / 映射 / 曲线 / 枚举搜索…）。

搜索的命中判定覆盖 **名称 / 翻译键 / 标题译文 / 注释译文**（`matchWithTranslate`）；命中项连同其全部祖先分组
进入过滤集，呈现时只取最上层的节点 —— 同一分组下的若干命中合并成**一个分组行**、组内只列命中的子项，分组行
在搜索期间默认展开。点任意分组项即清空关键词、回到该分组。关键词由页面自己持有（`TextFieldState`）。

```kotlin
@Composable
fun ConfigManagerWrapper(
    manager: ConfigManager,
    modifier: Modifier = Modifier,
    groupListMinWidth: Dp = ConfigManagerDefaults.GroupListMinWidth,
    groupListMaxWidth: Dp = ConfigManagerDefaults.GroupListMaxWidth,
)
```

想嵌进自己的模组屏幕，把 `ModScreen` 当外壳、这一页当内容即可（仓库自用屏 `mod/IbukiGourdModScreen.kt` 就是这么做的）。

## 2. 界面是怎么分发的

每个配置节点（`Config` / `ConfigGroup`）经 `ConfigUiWrapper(config)` 呈现，查找顺序是：

1. 节点自带的自定义 wrapper —— 构建期用 `uiWrapper { }` 指定；
2. `UIWrappers` 注册表里**第一个命中的谓词**（后注册者优先）；
3. 兜底 `UnspecifiedConfigWrapper`（显示名称 + `暂不支持（值类型名）`，新类型忘了注册也能看出缺的是哪个）。

内置已注册（`ConfigUIWrapper.kt` 的 `init`，后注册者优先）：`ConfigGroup` → `ConfigGroupWrapper`、
`ConfigManager` → `ConfigManagerWrapper`（整个管理器页；注册在分组之后所以优先命中）、基础值类型
（`Boolean` / `Int` / `Long` / `Float` / `Double` / `String`）、`CubicBezier` → `BezierCurveConfigWrapper`、
`ConfigEnum<*>` → `EnumConfigWrapper`、颜色（`nebula Color`）→ `ColorConfigWrapper`、`Duration` →
`DurationConfigWrapper`、`ConfigList<*>` → `ConfigListWrapper`、`ConfigMap<*>` → `ConfigMapWrapper`、
元素为 `Pair::class` 的列表 → `PairListConfigWrapper`、元素为 `CubicBezier::class` 的列表 →
`BezierListConfigWrapper`、`KeyCode`（`strict = false`）→ `KeyCodeConfigWrapper`、`ConfigKeybind` /
`ConfigToggleKeybind` → `KeybindConfigWrapper` / `ToggleKeybindConfigWrapper`，以及 6 种 JOML 向量
（`Vector2ic` / `Vector2fc` / `Vector2dc` / `Vector3ic` / `Vector3fc` / `Vector3dc`，均 `strict = false`）。

## 3. 换掉某一行的控件

```kotlin
val mode by configEnum("mode", ThemeMode.FollowSystem)
    .uiWrapper { config ->                      // 这一行完全由你决定怎么画
        var editing by remember { mutableStateOf(false) }
        EnumConfigWrapper(config) { selected -> if (selected == ThemeMode.Custom) editing = true }
        if (editing) MyEditorDialog(onDismiss = { editing = false })
    }
```

- `uiWrapper` 是 `ConfigNode` 的扩展（`fun <C : ConfigNode> C.uiWrapper(content: ConfigUIWrapper<C>): C`），
  **优先级高于类型分发**；重复调用以最后一次为准。注册在**分组**上时接管该分组页的整块内容（不再逐行铺排），
  可用 `ConfigNode.hasUIWrapper()` 判断节点有没有专用实现。
- **空实现 = 该行不出现在界面上**：`.uiWrapper { }`（仓库里 `custom_scheme` 这一项就这么藏起来，
  它的入口挂在同组的 `mode` 行上）。
- 行骨架的排版量走 `ConfigRowWrapper` 的 CompositionLocal（可在子树内整体覆盖）：`LocalPadding`、`LocalSpacing`、
  `LocalLevel`（嵌套层级，决定缩进）、`LocalIcon`（行首图标槽位）、`LocalBreadcrumb`（名称前的
  `所属分组 › ` 前缀，缺省 `null`；只有自行搭跨分组平铺列表时才需要提供）。
- 想在行内保留标准骨架（名称 / 重置 / tooltip），用 `ConfigRowWrapper`：

```kotlin
@Composable
fun ConfigRowWrapper(
    config: ConfigNode,
    modifier: Modifier = Modifier,
    horizontalArrangement: Arrangement.Horizontal = Arrangement.SpaceBetween,
    verticalAlignment: Alignment.Vertical = Alignment.CenterVertically,
    icon: (@Composable () -> Unit)? = ConfigRowWrapper.LocalIcon.current,
    resettable: Boolean = true,
    onClick: (() -> Unit)? = null,
    onReset: () -> Unit = {},
    hoverHighlight: Boolean = true,
    interactionSource: MutableInteractionSource? = null,
    content: @Composable RowScope.() -> Unit,      // 右侧控件放这里
)
```

## 4. 注册你自己类型的分发

消费方 MOD 可以在自己的初始化里给自定义类型注册 wrapper —— 这是配置界面**对外的扩展点**：

```kotlin
// 按配置的值类型（Config<T> 的 T）
UIWrappers.registerCheckValueType<MyVector>(strict = false) { MyVectorConfigWrapper(it) }

// 或按节点类型（strict = false 时接受子类）
UIWrappers.register<MySpecialConfig>(strict = false) { MySpecialConfigWrapper(it) }

// 最灵活：任意谓词，优先级最高
UIWrappers.register({ it is ConfigList<*> && it.elementType == MyThing::class }) {
    @Suppress("UNCHECKED_CAST")
    MyListWrapper(it as ConfigList<MyThing>)
}
```

- `registerCheckValueType<T>` 匹配的是**值类型**（`Config<T>` 的 `T`）；`strict = false` 才接受子类 /
  接口实现（例如 `Vector2fc` 之于 `Vector2f`）。
- `register<C>` 匹配**节点类型**；分组建议用谓词注册，因为 `object X : ConfigGroup("x")` 是子类，
  `strict = true` 会漏掉。
- `register(predicate, wrapper)` 的 wrapper 形参类型是 `ConfigUIWrapper<*>`，lambda 里的 `it` 只能当
  `ConfigNode` 用（要传给具体类型的 wrapper 得自己转型，见上面的例子）。
- 自己搭页面（不用 `ConfigManagerWrapper`）时：`ConfigsWrapper(configs)` 铺一组节点、`ConfigUiWrapper(node)`
  按注册表分发单个节点、`LocalSearchFilter` 在分组内做过滤。

## 5. 编辑弹窗与公共骨架

- `ConfigElementEditor` / `ConfigElementEditors`：列表 / 映射编辑弹窗里**单个值**的控件注册表（不带行骨架，
  按值类型匹配、后注册优先）。两者都带 `@Deprecated`，分发入口 `ConfigElementValue` 是 `internal`：给自己的
  编辑浮层配条目控件时直接传 Composable，不要再扩展这张表。
- `EnumSelector`（`EnumConfigWrapper.kt`）：行内枚举选择器，`selected` / `onSelect` / `items` 之外还有
  `content`、`itemContent`、`itemLeadingIcon` / `itemTrailingIcon`、`expandStyle`、`searchFilter`（缺省在
  选项多于 `ConfigControlDefaults.EnumSelectSearchThreshold` = 10 时挂搜索栏）。
- `StringValueField`（受控单行输入框，`value` / `onValueChange` / `isError`）与 `StringEditDialog`
  （多行文本浮层，确认时整段交回）：字符串配置与字符串元素共用，可单独复用。
- `ui.editdialog`：`EditDialog`（编辑副本、确认时快照交回）/ `EditDialogContent`（表头 + 浮动新增按钮 + 正文，
  浮动按钮随滚动显隐、按住隐藏动作键时收起）/ `EditDialogContentList`（表格式条目容器：可拖拽排序、
  右侧 flat 细条滚动条；行留白 `rowVerticalPadding`、图标倍率 `iconScale`、逐行修饰 `rowModifier` 可配，
  缺省整行悬停高亮）/ `EditDialogContentCards`（卡片网格容器：`columns` 指定列数，卡片头部 = 拖拽手柄 +
  可选 `title` 槽位 + 尾部 `actions` / `removeButton` 操作组）/ `DragHandle` /
  `RemoveButton` + `RemoveConfirmButton`（删除确认，按住「快速动作键」跳过确认，键可配）。
- `KeyedListState`（`ui/util/Keyed.kt`，由 `rememberKeyedList` 创建）：编辑浮层的条目容器 —— `entries` /
  `values` 读条目值，`add` / `removeAt` / `move` / `setValue` 改副本，`Keyed.key` 让重排 / 增删时组合状态
  跟数据走。
- `ConfigState`：`Config<T>.asState()` / `asDerivedState(forceRefresh = false) { }`（派生值）/
  `Resettable.asDefaultState()`（当前是否处于默认值，即重置按钮的可用态）—— 把配置订阅成 Compose `State`。
- `ConfigRowTheme.kt`：行的颜色与排版量声明 —— `ConfigRowTokens`（`Title` / `Comment` / `Icon` /
  `DisabledAlpha`，颜色走「调用点传参 > 作用域色 > 组件 token > 主题槽位」回退链）、
  `ConfigRowDefaults`（行距 / 缩进 / 图标倍率 / 注释行数 / 动画时长 / 滚动条与分割线厚度…）、
  `ConfigControlDefaults`（控件区宽度、曲线预览尺寸、滑条跨度上限、枚举搜索阈值…）、
  `ConfigDialogDefaults`（编辑浮层尺寸）、`ConfigRowPadding`、`configIconScale()`。
- 行内其它公共件：`ConfigControlBlock`（控件区固定总宽，保证各行控件左右对齐）、`configControlHeight()`、
  `ConfigName`、`ResetButton`、`ConfigDialogTitle`。

## 6. 文案

每一行 / 每个分组的标题、注释都取配置节点的翻译键（见 [02 配置系统](02-配置系统.md) 第 5 节）：

```jsonc
"your_mod_id.config.gui": "界面",
"your_mod_id.config.gui.comment": "界面相关设置",
"your_mod_id.config.gui.title": "标题",
"your_mod_id.config.gui.title.comment": "显示在屏幕上的标题",
```

界面骨架自己的文案（搜索 / 编辑 / 删除确认 / 重置…）在 `IGLang.Misc` / `IGLang.ConfigWrapper` 里，
语言文件是 `common/src/main/resources/assets/ibukigourd/lang/*.json`。
