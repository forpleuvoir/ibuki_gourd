# 05 事件总线

这章解决：**在正确的时机挂自己的逻辑**（生命周期 / 每帧 / 键鼠），以及**怎么取消事件**。

事件由 nebula 的 `EventFactory` 定义，IbukiGourd 提供 Minecraft 侧的事件对象。用法统一是
`事件.register { ... }`；触发方用 `事件.invoker().invoke(...)`（仓库里是 mixin 在调）。

## 1. 快速开始

```kotlin
import moe.forpleuvoir.ibukigourd.event.events.client.ClientLifecycleEvent

ClientLifecycleEvent.Starting.register { minecraft ->
    // 客户端初始化完成
}

ClientTickEvent.TickEnd.register { minecraft ->
    // 每 tick 末尾
}
```

## 2. 事件清单

### 客户端（`event/events/client/`）

| 事件 | 成员 | 回调参数 | 触发点 |
|---|---|---|---|
| `ClientLifecycleEvent` | `Starting` / `Stopping` / `OpenGameMenu` | `Minecraft` | 客户端启动、退出、打开游戏菜单（`MinecraftMixin`） |
| `ClientTickEvent` | `TickStart` / `TickEnd` | `Minecraft` | 每 tick 的首 / 尾（`MinecraftMixin`） |
| `ClientCommandRegistrationEvent` | 顶层 `val` | `context(CommandDispatcher<out SharedSuggestionProvider>, CommandBuildContext)()` | 加载器注册客户端指令时（见 [04 指令 DSL](04-指令DSL.md)） |

### 服务端（`event/events/server/`）

| 事件 | 成员 | 回调参数 |
|---|---|---|
| `ServerLifecycleEvent` | `Starting` / `Started` / `Stopping` / `Stopped` / `Saving` | `MinecraftServer` |
| `ServerCommandRegistrationEvent` | 顶层 `val` | `context(CommandDispatcher<CommandSourceStack>, CommandBuildContext, Commands.CommandSelection)()` |

### 输入（`event/events/client/input/`，均可取消）

| 事件 | 成员 | 上下文类型 | 上下文字段 |
|---|---|---|---|
| `KeyboardEvent` | `Pressed` / `Released` | `KeyboardEvent.KeyboardContext` | `keyCode`、`modifiers`、`isPressed`、`isRepeat`、`name`、`env`（`KeyEnvironment`），辅助方法 `isShiftPressed()` / `isCtrlPressed()` / `isAltPressed()` |
| `MouseEvent` | `Pressed` / `Released` | `MouseEvent.MouseKeyContext` | 同上（键码为鼠标键） |
| `MouseEvent` | `Scrolling` | `MouseEvent.ScrollingContext` | `xoffset`、`yoffset`、`env`（可取消） |
| `MouseEvent` | `Moving` | `MouseEvent.MovingContext` | 鼠标移动（可取消） |

## 3. 取消事件

键盘 / 鼠标事件的上下文实现 `CancellableContext`：

```kotlin
KeyboardEvent.Pressed.register { ctx ->
    if (ctx.keyCode == Keyboard.R && ctx.isShiftPressed()) {
        ctx.cancel()            // 吃掉这次按下，原版与其它监听者都收不到
    }
}
```

- `ctx.cancel(): Boolean` —— 只在**第一次**取消时返回 `true`（`AtomicBoolean` 比较交换）。
- `ctx.isCancelled(): Boolean` —— 触发方在回调之后据此决定是否放行；仓库的输入 mixin 就是这么做的
  （按键 / 鼠标事件被取消后不再转发给原版）。
- 捕获按键的 UI（`ui/keybind/KeySetter.kt`）正是靠"回调里直接 cancel"实现**连按住重复一起吞掉**：
  `InputHandler.onKeyPress` 对重复触发直接放行，只靠注册通配 `Keybind` 吞不掉 `GLFW_REPEAT`。

## 4. 注意事项

- **注册是全局的、不会自动注销**：`register { }` 返回的是 nebula 的订阅句柄（`Observable.Disposable`），
  生命周期内长期存在；需要临时监听就保存句柄并在合适时机 `dispose()`。
- **触发线程**：`KeyboardEvent` / `MouseEvent` 在**输入回调**里触发（渲染线程的输入阶段），
  `ClientTickEvent` 在主线程 tick 里；不要在键盘事件回调里做重活或写世界状态。
- **别在事件里再触发同一个事件**（递归）；要延后就用 `task` 包的 `scheduleStartTick`（见 [10 任务与工具](10-任务与工具.md)）。
- **`ClientCommandRegistrationEvent` / `ServerCommandRegistrationEvent` 是 `@JvmField val`**（不是 object），
  在 Java 侧按字段访问；Kotlin 侧正常用 `.register { }`。
- **事件定义里带上下文参数**（`context(...)` 函数类型）：在回调 lambda 里这些上下文是**隐式**可用的，
  所以你可以在里面直接调 `registerCommand(...)` 这类需要 dispatcher 的函数，但**不能按名字引用**它们。
