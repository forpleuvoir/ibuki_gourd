# 11 多加载器与平台抽象

定位：仓库是 common / fabric / neoforge 三段式，绝大多数代码写在 `common`；平台差异只有一处出口 —— `PlatformHelper`，经 `java.util.ServiceLoader` 由各加载器注入。

## 快速开始：消费方要做的两件事

**1. 在 mod 元数据里登记"我这个 mod 的包"** —— IbukiGourd 靠它扫描你带注解的配置 / 屏幕类：

```jsonc
// fabric/src/main/resources/fabric.mod.json
"custom": {
  "ibukigourd": { "package": "com.example.mymod" }
}
```

```toml
# neoforge/src/main/resources/META-INF/neoforge.mods.toml
[modproperties."mymod"]
package = "com.example.mymod"
```

**2. 想在自己的 `init()` 里注册东西，就加一个 `ModInitialization`**：

```kotlin
// 必须是带公开无参构造器的 class（ServiceLoader 要求），不能是 object
class MyModInitialization : ModInitialization {
    override fun init() {
        ClientModConfigHandler.register(MyConfig)
    }
}
```

```
src/main/resources/META-INF/services/moe.forpleuvoir.ibukigourd.platform.services.ModInitialization
```
文件内容是一行实现类的全限定名（多个实现写多行）：

```
com.example.mymod.MyModInitialization
```

库内的现成样例就是 `common/src/devOnly/resources/META-INF/services/moe.forpleuvoir.ibukigourd.platform.services.ModInitialization`，内容为 `moe.forpleuvoir.ibukigourd.test.TestInitialization`。

## 关键 API

### `platform/Services.kt`

| API | 签名 | 说明 |
|---|---|---|
| `Services.PLATFORM` | `val PLATFORM: PlatformHelper` | `ServiceLoader.load(PlatformHelper::class.java).findFirst()`，找不到就抛 `IllegalStateException("Failed to load service for ...")` |
| `Services.INITS` | `val INITS: List<ModInitialization>` | `ServiceLoader` 收集到的**全部** `ModInitialization` |
| `Services.load` / `loadAll` | `fun <T> load(clazz: Class<T>): T` / `fun <T> loadAll(clazz: Class<T>): List<T>` | 泛用的 ServiceLoader 封装 |
| 顶层 `PLATFORM` / `INITS` | `internal inline val` | 库内快捷方式，消费方直接用 `Services.PLATFORM` |
| `isDevEnv` | `val isDevEnv: Boolean by lazy { PLATFORM.isDevEnvironment() }` | 公开 |

调用时机：`IbukiGourd.init()` 依次执行 `INITS.forEach { it.init() }` 与本地 `inits`（目前是 `listOf(ServerModConfigHandler)`）。Fabric 侧由 `FabricIbukiGourd : ModInitializer` 调它，NeoForge 侧由 `NeoforgeIbukigourd` 在 `FMLCommonSetupEvent` 里调它。

### `platform/services/PlatformHelper.kt`

| 方法 | 作用 | Fabric | NeoForge |
|---|---|---|---|
| `getPlatformName(): String` | 平台名 | `"Fabric"` | `"Neoforge"` |
| `isModLoaded(modId: String): Boolean` | 某个 mod 是否加载 | `FabricLoader.isModLoaded` | `ModList.get().isLoaded` |
| `isDevEnvironment(): Boolean` | 是否开发环境 | `loader.isDevelopmentEnvironment` | `!FMLLoader.getCurrent().isProduction` |
| `getEnvironmentName(): String` | `"development"` / `"production"` | 接口默认实现，基于 `isDevEnvironment()` | 同左 |
| `getIGModClasses(): Map<String, Set<KClass<*>>>` | `modId` → 该 mod 在元数据 `package` 下声明的类 | 见下 | 见下 |
| `getConfigDir(): File` | 配置目录 | `loader.configDir.toFile()` | `FMLPaths.CONFIGDIR.get().toFile()` |

`getIGModClasses()` 的两种实现方式不同，且都懒加载、都跳过包名里含 `.mixin` 的类：

- **Fabric**（`FabricPlatformHelper`）：读 `mod.metadata.customValues["ibukigourd"].asObject["package"]`，用 Guava `ClassPath.getTopLevelClassesRecursive(pack)` 递归扫该包；**除类本身外还会把 `declaredClasses` 里的嵌套类一起放进集合**。
- **NeoForge**（`NeoforgePlatformHelper`）：读 `modInfo.modProperties["package"]`，遍历该 mod 文件 `scanResult.classes` 并按 `className.startsWith(value)` 过滤 —— **是字符串前缀匹配，不是包边界匹配**。

消费方一般不需要直接调它，用 `util/PackScanner.kt` 的 `scanModPackage { }` 即可（它就是在 `getIGModClasses()` 上套一层谓词过滤）。

### `platform/services/ModInitialization.kt`

```kotlin
fun interface ModInitialization : Initializable
```

`Initializable`（`init()`）来自 nebula。实现类必须可被 ServiceLoader 实例化。

## 依赖打包规则

`common` 只编译不传递，运行期由加载器侧把依赖嵌进 mod jar：

| 模块 | compose-minecraft | nebula / aseprite / reorderable |
|---|---|---|
| `common` | `compileOnly(libs.composeMinecraft.common)` | `compileOnlyApi(libs.nebula)`、`compileOnly(project(":aseprite"))`、`compileOnly(project(":reorderable"))` |
| `fabric` | `api(...)` + `include(...)` | 三者各自 `api(...)` + `include(...)` |
| `neoforge` | `api(...)` + `jarJar(...)` | 三者各自 `api(...)` + `jarJar(...)` |

- Fabric 侧 `include` 由 Loom 处理；NeoForge 的 `jarJar` **默认只嵌直接依赖**，所以 neoforge 另有 `bundledApi` 配置（`api` 已 `extendsFrom(bundledApi)`），并解析其完整传递依赖树后逐个提升为 `jarJar` 直接依赖（等价于 Loom 的 `jarJarInternal`）。
- 构件 pom 已排除 kotlin / kotlinx / annotations 传递依赖，所以这些库要逐个 `api + include`/`jarJar`。
- 构件从 `mavenLocal()` 解析。**改了 Compose-Minecraft 源码必须由作者手动发布一次**，否则本仓仍解析到旧构件，改了不生效 —— 助手只能提醒，发布动作由作者执行。

## 跨加载器写法约定

- **能放 `common` 就放 `common`**：`common` 的源码被加载器模块直接当 source 编译（`multiloader-loader.gradle` 把 `:common` 的 `commonJava` / `commonKotlin` / `commonResources` 三个 configuration 加进 `source(configurations.xxx)`），所以 common 里的类最终就在加载器 jar 内，不是嵌套 jar。**不要在 common 里硬编码平台判断**，平台能力一律走 `PlatformHelper`。
- **再加一个平台能力**：往 `PlatformHelper` 加方法并在 `FabricPlatformHelper` / `NeoforgePlatformHelper` 各实现一份；**再加一个加载器**：在 `settings.gradle.kts` 里 `include(...)`，新模块套 `id("multiloader-loader")` 并在自己的 `META-INF/services/` 下注册 `PlatformHelper` 实现。
- **Mixin**：Java 源码放 `common/src/main/java/moe/forpleuvoir/ibukigourd/mixin/`（客户端相关放 `mixin/client/`），在 `common/src/main/resources/ibukigourd.mixins.json` 注册（该文件已被两个加载器的元数据引用）；仅有单加载器差异的放 `ibukigourd.fabric.mixins.json` / `ibukigourd.neoforge.mixins.json`。
- **访问拓宽**：Fabric 用 `common/src/main/resources/ibukigourd.classtweaker`（`fabric.mod.json` 的 `accessWidener` 字段 + `fabric/build.gradle.kts` 里 `loom.accessWidenerPath` 都指向它）；NeoForge 用 `common/src/main/resources/META-INF/accesstransformer.cfg`（由 `common/build.gradle.kts` 的 `neoForge.accessTransformers.from(...)` 读取）。
- **元数据占位符**：`fabric.mod.json` / `*.mixins.json` / `pack.mcmeta` / `META-INF/{,neoforge.}mods.toml` 会被 `processResources` 用 `gradle.properties` 与 `libs.versions.toml` 展开，新增版本字段一律写 `${...}` 占位符。

## 注意事项

- **`getIGModClasses()` 是懒加载的全局缓存**：它在首次访问时就把所有 mod 的类扫完并缓存，不会随运行期新注册而更新。必须在 `IbukiGourd.init()` 之前就绪的信息不要指望它。
- **两个实现的过滤口径不同**：Fabric 递归扫包并把嵌套类一并收进集合；NeoForge 是类名前缀匹配（`startsWith(package)`），把 `com.example.mymod` 配成 `package` 会同时命中 `com.example.mymodx.Foo`。写 `package` 时给出完整、不与其他包互为前缀的包名。
- **`ModInitialization` 不能是 `object`**：ServiceLoader 通过反射构造实例，需要公开无参构造器。注册文件路径与文件名必须逐字是接口的全限定名。
- **`PLATFORM` 找不到实现时直接抛异常**：`META-INF/services/...PlatformHelper` 只存在于 fabric / neoforge 模块；在 `common` 里单独跑（例如脱离加载器的单元测试）会拿到 `IllegalStateException`。
- **`Services.PLATFORM` 不可用于服务端专用代码的判断**：它回答的是"加载器 / 环境"，不是"当前侧"；侧别判断请用原版 `FMLEnvironment` / `FabricLoader.getEnvironmentType()` 或自己的逻辑。
- **common 的资源会被两个加载器同时打包**：`common/src/main/resources` 下的 mixins json、AW、assets、lang 对 fabric 与 neoforge 都生效；只有加载器专属的资源才放进各自的 `src/main/resources`。
