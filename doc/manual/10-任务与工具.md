# 10 任务与工具

定位：`task` 包提供"下个 tick 再执行 / 每隔 N tick 执行 M 次"的调度器与任务抽象；`util` 和 `util.math*` 是随取随用的零散助手。

## 快速开始

```kotlin
import moe.forpleuvoir.ibukigourd.task.scheduleStartTick   // 客户端：顶层扩展

// 客户端：延迟 20 tick 执行一次
mc.scheduleStartTick(delay = 20) { _, client ->
    client.player?.displayClientMessage(MiscLang.confirm, false)
}

// 服务端：每 40 tick 一次、共 5 次
with(TickTaskScheduler.Companion) {
    server.scheduleStartTick(TickTask(delay = 0, period = 40, times = 5) { task, srv ->
        srv.playerList.broadcastSystemMessage(buildText { literal("tick") }, false)
    })
}
```

调度器由库自带的 mixin 驱动，不需要消费方做任何注册：`mixin/client/MinecraftMixin.java` 在 `Minecraft.tick` 的 HEAD / RETURN 分别调用 `startTick` / `endTick`，`mixin/MinecraftServerMixin.java` 在 `MinecraftServer.tickServer` 的 HEAD / RETURN 同理。

## 关键 API

### 任务模型（`task/TickTask.kt`、`task/TaskExecutor.kt`）

| API | 签名 | 说明 |
|---|---|---|
| `TickTask` | `TickTask(delay: Int = 0, period: Int = 1, times: Int = 1, action: (TickTask<T>, T) -> Unit)` | 也有收 `executor: TaskExecutor<T>` 的重载与收 `Setting` 的主构造器 |
| `TickTask.Setting` | `Setting(delay: Int = 0, period: Int = 1, times: Int = 1)` | 可序列化；`delay >= 0`、`period >= 1`、`times >= 1`（`init` 里 `check`） |
| 字段 | `delay` / `period` / `times` / `counter` / `isOver` | `counter` 由执行累加，`isOver` 即 `counter >= times` |
| `tryExecute` | `tryExecute(context: T)` | 由调度器调用；先判 `isOver`，再按 `delay`/`period` 计数 |
| `TickTask.fromTask` | `TickTask.fromTask(task: TickTask<T>): TickTask<T>` | 复制 delay/period/times/executor 造一个新任务（计数从 0 起） |
| `TaskExecutor` | `interface TaskExecutor<T> : Serializable { fun execute(task: TickTask<T>, context: T) }` | `Serializable` 来自 nebula，调度器不依赖它 |
| `TaskExecutor.Companion.createTask` | `fun <T, E : TaskExecutor<T>> E.createTask(delay: Int = 0, period: Int = 1, times: Int = 1): TickTask<T>` | |
| `SimpleTaskExecutor` | `fun interface SimpleTaskExecutor<T> : TaskExecutor<T>` | lambda 版；`serialization()` 返回 `SerializeNull` |

时序：`counter == 0` 时按 `delay` 计数（`delay = 0` 首个 tick 即执行），之后按 `period` 计数；`period` 是**两次执行之间的间隔**。

### 调度器（`task/TickTaskScheduler.kt`、`task/ClientTickTaskScheduler.kt`）

| API | 签名 | 说明 |
|---|---|---|
| `TickTaskScheduler<T>` | `open class TickTaskScheduler<T>` | 内部是两个 `ConcurrentLinkedQueue`（start / end），可从任意线程投递 |
| 投递 / 移除 / 查询 | `scheduleStartTick(delay: Int = 0, action: (TickTask<T>, T) -> Unit)` / `scheduleEndTick(...)`；`remove(task)` / `clear()`；`tasks` / `startTasks` / `endTasks` | 投递另有收 `TickTask<T>` 的重载；`remove` **延迟生效**（入待删队列，下次 tick 派发时才真正摘掉）；查询返回快照列表 |
| 客户端单例 | `TickTaskScheduler.Client`（`ClientTickTaskScheduler.kt:7` 的 `val TickTaskScheduler.Companion.Client`，伴生对象上的扩展属性） | `TickTaskScheduler<Minecraft>` |
| 服务端单例 | `TickTaskScheduler.Server`（companion 内 `@JvmStatic val`） | `TickTaskScheduler<MinecraftServer>` |
| 客户端扩展 | `Minecraft.scheduleStartTick(task/action/delay+action)`、`Minecraft.scheduleEndTick(...)`、`Minecraft.scheduleStopTick(...)` | `task` 包顶层，直接 import |
| 服务端扩展 | 同名，但定义在 `TickTaskScheduler.Companion` 内 | 需要 companion 在作用域：`with(TickTaskScheduler.Companion) { ... }` |

### 协程（`nebula` + `kotlinx.coroutines`）

## 常见用法

### 1. 一次性延后（客户端）

```kotlin
// 等到玩家与关卡都就绪
mc.scheduleStartTick(delay = 1) { _, client ->
    val level = client.level ?: return@scheduleStartTick   // 关卡 / 玩家都就绪后再动手
    val player = client.player ?: return@scheduleStartTick
}
```

### 2. 周期任务 + 手动终止

```kotlin
// times 给定次数后自动结束；要提前结束用调度器把任务摘掉（见「注意事项」）
val task = TickTask<Minecraft>(delay = 0, period = 10, times = 20) { t, client ->
    println("第 ${t.counter} 次")
}
mc.scheduleStartTick(task)
mc.scheduleEndTick { _, _ -> /* 每 tick 末尾 */ }
```

### 3. 自有 `TaskExecutor`（可序列化的任务）

```kotlin
object ReportExecutor : TaskExecutor<MinecraftServer> {
    override fun execute(task: TickTask<MinecraftServer>, context: MinecraftServer) {
        context.playerList.broadcastSystemMessage(Literal("report"), false)
    }

    override fun serialization(): SerializeElement = SerializeNull
    override fun asString(): String = "ReportExecutor"
}

val task = ReportExecutor.createTask<MinecraftServer, ReportExecutor>(delay = 0, period = 20, times = 3)
TickTaskScheduler.Server.scheduleStartTick(task)
```

### 4. 后台 IO 后再回主线程

```kotlin
val deferred = modConfigManager.asyncSave()      // ioAsync，IO 调度器
ioLaunch {
    val cost = deferred.await()                  // 不阻塞调用线程
    Minecraft.getInstance().scheduleStartTick { _, _ -> logger.info("saved in $cost") }
}
```

## 注意事项

- **`scheduleStopTick` 走的是 start tick 队列**：它的实现是 `Client.scheduleStartTick { _, _ -> task() }`，名字里的 "Stop" 不表示 tick 末尾 —— 要在 tick 末尾执行请用 `scheduleEndTick`。
- **服务端的 `MinecraftServer.scheduleStartTick(...)` 定义在 companion 里**，必须让 companion 进作用域（`with(TickTaskScheduler.Companion) { ... }`）或直接调 `TickTaskScheduler.Server.scheduleStartTick(...)`；客户端版本是顶层扩展，直接 import 即可。
- **`remove()` 不是立即生效**：任务被放进待删队列，下一次 `startTick` / `endTick` 派发时才摘除。`counter` 只有 `private set`，外部无法直接改写它来提前结束任务，请用 `remove(task)` 或 `clear()`。
- **`TickTask` 的 `delay` / `period` / `times` 在 `init` 里 `check`**：`delay < 0`、`period < 1`、`times < 1` 直接抛 `IllegalStateException`。`delay = 0` 表示"当 tick 就执行"，不是"跳过第一次"；`period` 是两次执行之间的间隔，不是执行次数。
- **`SimpleTaskExecutor` 不可持久化**：它重写的 `serialization()` 返回 `SerializeNull`，`TickTask` 的序列化只在传入实现了真实 `TaskExecutor` 时才有意义。
- **别在 tick / 渲染线程上 `runBlocking`**：库内只在启动、停止这类一次性生命周期节点用。要等 IO，用 `ioAsync` + `ioLaunch { deferred.await() }`，或把结果用 `scheduleStartTick` 投回主线程。`ioLaunch` / `ioAsync` 跑在 IO 调度器上，内部不要读写 `World` / `Entity` / `GuiGraphics` / Compose 状态。
- **`Any.logger()`（无参）与 `logger(kClass)`、`logger(name)` 都是 `internal`**：消费方请用公开的 `Any.logger(modName: String)` 或 `ModLogger(clazz: KClass<*>, modName: String)`，别指望日志名自动带自己的 modId。
- **缓动的两个坑**：非 `Custom` 的 `EasingPreset` 会忽略传入的 `custom` 曲线；`BackOut` / `BounceOut` / `ElasticOut` 来自 `EasingCurve` 而非四次贝塞尔，无法用四点表达。`Easing.LINEAR` 是全等映射（三个方法都返回 `t`）。
