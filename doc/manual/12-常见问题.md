# 12 常见问题

清单式：**症状 → 原因 → 做法**。只列在当前分支（26.2，Sokitsu UI + compose-minecraft）上仍然成立的技术事实。

## 像素缩放与尺寸

### 界面整体比例怪、组件外框和框内素材对不上

- **症状**：九宫格边框显得过粗或过细，组件外框与素材比例不一致。
- **原因**：一档缩放里有两个量 —— `SokitsuScreenScale.density`（布局尺寸，`dp`/`sp` → 屏幕像素）与 `pixelScale`（1 素材像素 → N 屏幕像素）。**只改其中一个**，两者就错位。
- **做法**：两者必须**同向变化**。用 `SokitsuScreenRoot`（`ui/sokitsu/SokitsuScreen.kt`）包住内容即可 —— 它按窗口像素尺寸调 `SokitsuScreenDefaults.resolver`，一次下发 `LocalDensity` 与主题 `pixelScale`。要自定义分档就整体替换 `SokitsuScreenDefaults.resolver`（`SokitsuScreenScaleResolver`）。

### 窄窗口下界面挤爆 / 突然整体缩小

- **症状**：同一屏幕在一台机器上正常，窗口拉小后所有东西缩了一半。
- **原因**：`SokitsuScreenDefaults` 的默认策略是"窗口宽高**同时**达到 `threshold` 用 `baseFactor`（1f），否则用 `compactFactor`（0.5f）"。`threshold` 缺省是 `IntSize(Window.BASE_WIDTH * 3, Window.BASE_HEIGHT * 3)` = 960×720。
- **做法**：调 `SokitsuScreenDefaults.threshold`（只改倍数 N 即可换边界）或 `baseFactor` / `compactFactor`。注意倍率小于 1 时 `pixelScale` 无法整除（3 × 0.5 = 1.5），默认实现按四舍五入并下限 1；要精确控制就替换 `resolver`。

### dp ↔ px 到底怎么换

- **症状**：自写组件按"素材像素 × 倍率"算尺寸，结果偏大 / 偏小 / 随窗口漂移。
- **原因**：`dp.value * pixelScale` 丢掉了密度；`dp.toPx() * pixelScale` 把倍率乘了两遍。
- **做法**：唯一的换算入口是 `with(LocalDensity.current) { dp.toPx() }`。像素风约定里"1 设计像素 = 素材画布 1 像素"，在基准档下正好等于 `pixelScale.dp`；几何数值应登记进组件 meta（`Codec.dp`）再在 `@Composable @ReadOnlyComposable` getter 里乘 `LocalSokitsuPixelScale`，别在组件内写死常量再折算。

### 图标尺寸不跟着像素倍率走

- **症状**：`Icon(Icons.Add)` 比周围素材小一圈，改 `SokitsuThemeMeta.pixelScale` 也不变。
- **原因**：`Icon` 的 `scale: Int = 2` 是字面量缺省值，**不自动读** `LocalSokitsuPixelScale`（其 KDoc 写的是"默认跟随"，与签名不一致）。
- **做法**：需要联动就显式传 `scale = LocalSokitsuPixelScale.current`。另外 `Icon` 在父级约束放不下时会自动降到"能放下的最大整数倍率"（宁可变小也不非等比拉伸）；传 `size` 则完全接管、不做这层收缩。

## 布局与提示

### Tooltip 把父级布局挤歪 / 多出一块空白

- **症状**：给 `Row` 里的元素挂 `Modifier.tooltip(...)` 后，`Arrangement.SpaceBetween` 之类的结果不对。
- **原因**：早期的 `Popup()` 是发射进父组合作用域的。
- **做法**：现在的 `Tooltip` / `BasicTooltip` 经 `LocalPopupHost` 注册到**场景根**，**不产生布局节点**，无需 `Box` 包裹锚组件，也不会参与父布局的 child 计数。若仍出现占位，检查是不是自己多包了一层容器。`pinned = true` 时跳过悬停延迟直接展示，且弹层不再被外部点击关闭。

### 滚动时崩溃 / 卡死

- **症状**：滚动容器滚动过程中游戏卡住或抛异常，日志里是测量 / 快照相关。
- **原因**：滚动事件在派发期发生，此时**在组合期或协程里写快照状态**会与本平台的测量 / 快照锁撞成永久死等。
- **做法**：显隐、进度这类由滚动驱动的状态，在嵌套滚动回调里维护，不要在 `LaunchedEffect` / 协程里回写（`ui/util/FabVisibility.kt` 的 `onPreScroll` 就是正确写法，其 KDoc 明确写了这条约束）；滚动驱动的高频显隐也不要挂 `Modifier.fabVisibilityAnimation`（每帧重录图层），直接用 `FabVisibilityState` 控制组合。

### 自定义 `Layout` / `SubcomposeLayout` 抛 `IllegalStateException`

- **症状**：`measure() may not be called multiple times on the same Measurable. ...`
- **原因**：同一个 `Measurable` **只能 `measure()` 一次**（compose-minecraft 的 `androidx/compose/ui/node/LayoutNodeLayoutDelegate.kt` 里 `MeasuredTwiceErrorMessage` 仍然生效），"先无界探一次、再按真实约束量一次"的两趟测量会直接抛异常，用户端表现为游戏崩溃。
- **做法**：要换约束量第二趟，只能**重新 subcompose**，并配 `resetIndices(start)` 让第二趟里"第一个"子项的下标与主趟一致；只想知道内容尺寸就用 `minIntrinsicWidth()` / `maxIntrinsicWidth()` / `minIntrinsicHeight()` / `maxIntrinsicHeight()`。

## 配置 GUI

### 某个配置项不想显示 / 想换成自定义控件

- **症状**：配置项在配置页里多出来一行，或者行的呈现不符合需求。
- **原因**：`ConfigUIWrapper` 的查找顺序是「节点自带的 `uiWrapper` → `UIWrappers` 里第一个命中的谓词 → `UnspecifiedConfigWrapper` 兜底」。
- **做法**：在配置项构造链上挂 `uiWrapper`。整行不出用空实现：

  ```kotlin
  val customScheme by customSchemeConfig.uiWrapper { }   // 不出行，入口挂到别的行上
  ```

  换成自己的控件就用 lambda 形式，参数是配置节点本身：

  ```kotlin
  val mode by modeConfig.uiWrapper { config ->
      EnumConfigWrapper(config) { selected -> /* ... */ }   // config 类型为 ConfigNode
  }
  ```

  重复调用以最后一次为准。整类型统一改，注册进 `UIWrappers` 而不是逐个挂。

## 资源与素材

### 加了 `.aseprite` 但界面里是空的

- **症状**：`Icon` / 组件精灵画不出来，或者尺寸为 0。
- **原因**：素材目录与纹理 id 必须严格对上，且图集是**运行时程序化构建**、随资源重载整体刷新。
- **做法**：
  - 素材放 `assets/<ns>/texture/sokitsu/<atlasId>/` 下任意深度，`.aseprite` 文件会被**递归自动扫描**；
  - 图集定义放 `assets/<ns>/sokitsu_atlas/<atlasId>.json`（现有 `ui` / `icon`；`SokitsuAtlasManager.DEFAULT_ATLAS_ID` 为 `sokitsu`，库内未提供其定义文件，留给资源包）；
  - **纹理 id = 文件路径去掉 `texture/sokitsu/` 前缀与 `.aseprite` 后缀**，如 `texture/sokitsu/icon/add.aseprite` → `ibukigourd:icon/add`；
  - 素材改动后按 `F3 + T` 重载资源。

### 主题 meta 文件在哪

- **症状**：想改配色 / 像素倍率，找不到 `sokitsu_meta.json`。
- **原因**：`assets/ibukigourd/sokitsu_meta.json` 是**资源包自定义入口**，库内默认不提供，缺失时全部走内置默认值。
- **做法**：自己做资源包，按 `SokitsuThemeMeta` 的结构提供该文件。

## i18n 与文档规范

- **症状**：中文里把快捷键设置写成了"按键绑定"。
- **规范**：`keybind`（`Keybind` / 键位绑定）→ 译 **"快捷键"**；单纯的按键码 `keycode` → 译 **"按键"**。新文案登记到 `IGLang` 子对象，资源文件在 `assets/ibukigourd/lang/<locale>.json`，键名规则见第 07 章。
- **注释规范**：注释与文档用中文，**只写当前代码的技术事实**（方法行为、参数含义、取值/单位、边界与回落策略）；不写"为什么这么改""之前有 bug""与别的实现对比"这类来龙去脉。

## 开发与构建

### 测试代码放哪 / 为什么我的测试类没进 jar

- `src/test/**` 默认被 `.gitignore` 忽略，**仓内唯一纳入版本管理的测试源集是 `aseprite/src/test`**。
- 开发期测试代码放 `common/src/devOnly/`：`kotlin/.../test/`（测试屏、测试配置、`igtest` 指令）、`resources/META-INF/services/`（开发期 `ModInitialization` 注册）。Fabric 的 client dev 运行配置使用该源集。
- `igtest config_keys` dump 的目标目录 `common/src/devOnly/lang` 也在 `.gitignore` 里。

### 改了 Compose-Minecraft 源码却不生效

- **原因**：构件从 `mavenLocal()` 解析 —— 未发布时本仓仍解析到 mavenLocal 里的**旧构件**。
- **做法**：由 Compose-Minecraft 作者手动发布 / 推送一次（发布动作不由助手执行）。调试本地版本时在 `~/.m2/repository/moe/forpleuvoir/` 下确认版本。

### 依赖应该写 `compileOnly` 还是 `api + include/jarJar`

- `common` 侧一律 `compileOnly`：`compileOnly(libs.composeMinecraft.common)`、`compileOnlyApi(libs.nebula)`、`compileOnly(project(":aseprite"))`、`compileOnly(project(":reorderable"))` —— 只编译、不传递，打包由加载器侧负责。
- 加载器侧负责把运行期依赖嵌进 mod jar：fabric 用 `api + include`，neoforge 用 `api + jarJar`（neoforge 的 `jarJar` 默认只嵌直接依赖，传递树由 `bundledApi` + `jarJarInternal` 逐个提升）。
- 新增 UI 依赖请沿用同一模式，并在两个加载器侧都补上。
