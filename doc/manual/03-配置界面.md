# 03 配置界面

这章解决：**把配置管理器变成界面**，以及**怎么改某个配置项的呈现方式**。

## 1. 最小用法

```kotlin
SokitsuScreen.open {                    // 主题 + 分辨率缩放（见 08 章）
    ConfigManagerWrapper(YourModConfigs)
}
```

`ConfigManagerWrapper` 自带：跨分组搜索（结果按面包屑平铺）、页签导航、分组列表、每一行"名称 + 控件 +
重置 + tooltip"，以及各类型的编辑弹窗（列表 / 映射 / 曲线 / 枚举搜索…）。

```kotlin
@Composable
fun ConfigManagerWrapper(
    manager: ConfigManager,
    modifier: Modifier = Modifier,
    groupListMinWidth: Dp = ConfigManagerDefaults.GroupListMinWidth,
    groupListMaxWidth: Dp = ConfigManagerDefaults.GroupListMaxWidth,
)
```

想嵌进自己的模组屏幕，把 `ModScreen` 当外壳、这一页当内容即可（仓库自用屏 `mod/IbukiGourdModScreen.kt` 就是这么做的）。

## 2. 界面是怎么分发的

每个配置节点（`Config` / `ConfigGroup`）经 `ConfigUiWrapper(config)` 呈现，查找顺序是：

1. 节点自带的自定义 wrapper —— 构建期用 `uiWrapper { }` 指定；
2. `UIWrappers` 注册表里**第一个命中的谓词**（后注册者优先）；
3. 兜底 `UnspecifiedConfigWrapper`（未知类型也至少能显示）。

内置已注册（`ConfigUIWrapper.kt` 的 `init`）：分组、`Boolean` / `Int` / `Long` / `Float` / `Double` /
`String`、`CubicBezier`、`ConfigEnum`、颜色（`nebula Color`）、`Duration`、`ConfigList` / `ConfigMap`、
键值对列表、曲线列表、`KeyCode`、`ConfigKeybind`、`ConfigToggleKeybind`，以及 6 种 JOML 向量。

## 3. 换掉某一行的控件

```kotlin
val mode by configEnum("mode", ThemeMode.FollowSystem)
    .uiWrapper { config ->                      // 这一行完全由你决定怎么画
        var editing by remember { mutableStateOf(false) }
        EnumConfigWrapper(config) { selected -> if (selected == ThemeMode.Custom) editing = true }
        if (editing) MyEditorDialog(onDismiss = { editing = false })
    }
```

- `uiWrapper` 是 `ConfigNode` 的扩展（`fun <C : ConfigNode> C.uiWrapper(content: ConfigUIWrapper<C>): C`），
  **优先级高于类型分发**；重复调用以最后一次为准。
- **空实现 = 该行不出现在界面上**：`.uiWrapper { }`（仓库里 `custom_scheme` 这一项就这么藏起来，
  它的入口挂在同组的 `mode` 行上）。
- 想在行内保留标准骨架（名称 / 重置 / tooltip），用 `ConfigRowWrapper`：

```kotlin
@Composable
fun ConfigRowWrapper(
    config: ConfigNode,
    modifier: Modifier = Modifier,
    horizontalArrangement: Arrangement.Horizontal = Arrangement.SpaceBetween,
    verticalAlignment: Alignment.Vertical = Alignment.CenterVertically,
    icon: (@Composable () -> Unit)? = ConfigRowWrapper.LocalIcon.current,
    resettable: Boolean = true,
    onClick: (() -> Unit)? = null,
    onReset: () -> Unit = {},
    hoverHighlight: Boolean = true,
    interactionSource: MutableInteractionSource? = null,
    content: @Composable RowScope.() -> Unit,      // 右侧控件放这里
)
```

## 4. 注册你自己类型的分发

消费方 MOD 可以在自己的初始化里给自定义类型注册 wrapper —— 这是配置界面**对外的扩展点**：

```kotlin
// 按配置的值类型（Config<T> 的 T）
UIWrappers.registerCheckValueType<MyVector>(strict = false) { MyVectorConfigWrapper(it) }

// 或按节点类型（strict = false 时接受子类）
UIWrappers.register<MySpecialConfig>(strict = false) { MySpecialConfigWrapper(it) }

// 最灵活：任意谓词，优先级最高
UIWrappers.register({ it is ConfigList<*> && it.elementType == MyThing::class }) { MyListWrapper(it) }
```

- `registerCheckValueType<T>` 匹配的是**值类型**（`Config<T>` 的 `T`）；`strict = false` 才接受子类 /
  接口实现（例如 `Vector2fc` 之于 `Vector2f`）。
- `register<C>` 匹配**节点类型**；分组建议用谓词注册，因为 `object X : ConfigGroup("x")` 是子类，
  `strict = true` 会漏掉。
- 自己搭页面（不用 `ConfigManagerWrapper`）时，可用 `LocalSearchFilter` 在分组内做过滤。

## 5. 编辑弹窗与公共骨架

- `ConfigElementEditor`：编辑弹窗内**按值的运行时类型**取控件（不带行骨架），给自己写编辑弹窗时复用。
- `ui.editdialog`：`EditDialog`（编辑副本、确认时快照交回）/ `EditDialogContent`（表头 + 浮动新增按钮 + 正文）/
  `EditDialogContentList`（可拖拽排序的行列表）/ `EditDialogContentCards`（卡片网格容器）/ `DragHandle` /
  `RemoveButton` + `RemoveConfirmButton`（删除确认，按住「快速动作键」跳过确认，键可配）。
- `ConfigState`：`Config<T>.asState()` / `asDerivedState { }` / `asDefaultState()` —— 把配置订阅成 Compose `State`。
- `ConfigRowTheme`：配置行的组件 token 声明（颜色走「调用点传参 > 组件 token 表 > 主题槽位」回退链）。

## 6. 文案

每一行 / 每个分组的标题、注释都取配置节点的翻译键（见 [02 配置系统](02-配置系统.md) 第 5 节）：

```jsonc
"your_mod_id.config.gui": "界面",
"your_mod_id.config.gui.comment": "界面相关设置",
"your_mod_id.config.gui.title": "标题",
"your_mod_id.config.gui.title.comment": "显示在屏幕上的标题",
```

界面骨架自己的文案（搜索 / 编辑 / 删除确认 / 重置…）在 `IGLang.Misc` / `IGLang.ConfigWrapper` 里，
语言文件是 `common/src/main/resources/assets/ibukigourd/lang/*.json`。
