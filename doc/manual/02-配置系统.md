# 02 配置系统

这章解决：**怎么声明配置项、怎么读它、什么时候被保存**。配置框架本体来自依赖库
[nebula](https://github.com/forpleuvoir)（`ConfigManager` / `Config` / `ConfigGroup` / `Codec` / `ConfigSerde`），
IbukiGourd 补上 Minecraft 相关的类型（快捷键、向量、颜色…）与"注册即托管"的处理器。

## 1. 快速开始

```kotlin
object YourModConfigs : ClientModConfigManager("your_mod_id", "config") {

    init { addConfig(Gui) }                       // 挂到根上

    object Gui : ConfigGroup("gui") {

        private val titleConfig = configString("title", "Hello")
        val title by titleConfig                   // 委托读出来的是值（String）

        val scaleConfig = configFloat("scale", 1f, 0.5f, 2f)   // 带范围 → 界面用滑条
        var scale by scaleConfig                  // var 委托：读写都落到这个 Config 上

        private val openKeyConfig = configKeybind("open_key", Keybind(Keyboard.RIGHT_SHIFT))
        val openKey by openKeyConfig
    }
}

ClientModConfigHandler.register(YourModConfigs)   // 注册后生命周期自动托管
```

- `ClientModConfigManager(modId, name)` / `ServerModConfigManager(modId, name)`：一个 `name` 一个文件
  （客户端落在 `<加载器配置目录>/<modId>/<name>.yml`，目录见 `PlatformHelper.getConfigDir()`）。
- **配置项是属性委托**（`ConfigValued.getValue` / `setValue`）：`val x by cfg` 只读、`var x by cfg` 可写，
  两种写法读出来的都是**值本身**（`String` / `Float` / `Keybind`…），不是 `Config` 对象。
  所以要在节点上调 `observe { }` / `resetDefault()` / `uiWrapper { }` 时，得把那个 `Config` 另存一份
  （上面的 `scaleConfig` 就是干这个的；不需要节点本身的项可以直接 `private val xxxConfig = configXxx(...)`）。
- **构造器是 `context(ConfigGroup)` 扩展**：只能在 `ConfigGroup` 内调用（见手册首页的编译参数说明）。

## 2. 配置项构造器一览

### 2.1 nebula 提供（数值 / 文本 / 集合 / 颜色 / 时长 / 枚举）

| 构造器 | 说明 |
|---|---|
| `configString(name, defaultValue)` | 字符串 |
| `configChar(name, defaultValue)` | 单字符 |
| `configBoolean(name, defaultValue)` | 开关（返回 `ConfigBoolean`，另有 `toggle()`） |
| `configByte` / `configShort` / `configInt` / `configLong` / `configFloat` / `configDouble` | 数值，签名 `(name, defaultValue, minValue = 类型下限, maxValue = 类型上限)`；界面据此用滑条 / 数字框 |
| `configDuration(name, defaultValue, minDuration = Duration.ZERO, maxDuration = Duration.INFINITE)` | `kotlin.time.Duration` |
| `configColor(name, defaultValue)` | 颜色（nebula `Color`，界面用取色器） |
| `configEnum(name, default)` | 枚举，按 `Enum.name` 序列化（走 `Codec.enum()`） |
| `configList(name, defaultValue, elementSerde)` / `configMap(name, defaultValue, entrySerde)` | 列表 / 映射；第三个参数可传 `ConfigSerde`、`Codec` 或 `KSerializer` |
| `config(name, defaultValue, serdeOrCodecOrSerializer)` / `ConfigItem(name, defaultValue, ConfigSerde.of(...))` | 自定义结构（自己写 `Codec` / 用 `ConfigSerde.of`） |

### 2.2 本仓新增（`config/item/`）

| 构造器 | 说明 |
|---|---|
| `configKeybind(name, defaultValue: Keybind)` | 一段按键组合（配置项自身可变，见 [06 输入与快捷键](06-输入与快捷键.md)） |
| `configKeybind(name, vararg defaultKeys: KeyCode, setting: KeybindSetting = KeybindSetting(), action: Keybind.() -> Unit)` | 同一个键位配置项 + 直接给按下时动作 |
| `configToggleKeybind(name, defaultEnabled: Boolean, defaultValue: Keybind, onSwitch: ConfigToggleKeybind.() -> Unit)` | 开关式快捷键：`enabled` 与 `keybind` 一起存；**不传 `onSwitch` 时会弹一条「组 → 配置名 : 开/关」的 Toast**（tag 取配置路径 `toggle_keybind:<路径>`，连按只刷新同一条） |
| `configToggleKeybind(name, defaultEnabled: Boolean, vararg defaultKeys: KeyCode, setting: KeybindSetting = KeybindSetting(), onSwitch = ...)` | 同上，直接用按键声明 |
| `configKeyCode(name, defaultValue: KeyCode)` | 单个按键码（不是组合键） |
| `configVector2i/2f/2d`、`configVector3i/3f/3d`（`name, defaultValue, minValue, maxValue`） | JOML 向量，带范围；`Config.range`（扩展属性，可空）可读回 `Pair<向量, 向量>`，元素是 JOML 只读接口（如 `Vector2fc`） |
| `configEnum(name, default, codec)` | 与 nebula 同名同形，但**允许指定枚举自己的 `Codec`**（要写小写字面量如 `"cubic"` 时用） |
| `configStringPair(name, defaultValue: Pair<String, String>)` / `configPair(name, defaultValue, serdeA, serdeB)` | 键值对 |
| `configPairList(name, defaultValue: List<Pair<A, B>>, serdeA, serdeB)` | 键值对列表（界面按列表 + 编辑弹窗呈现） |

> 上表除 `configEnum` 外都返回对应的 `Config` 节点；读取值请用属性委托 `val x by config*`。

## 3. 读取、观测与默认值

```kotlin
// 直接读委托属性（拿到的是值）——快速开始里的 title / scale / openKey
val scaleNow: Float = YourModConfigs.Gui.scale

// 观测 / 重置都要在 Config 节点上做，所以另外留一份节点引用
YourModConfigs.Gui.scaleConfig
    .observe { cfg -> ScreenAnimationDefaults.slideFraction = cfg.getValue() }   // 返回可 dispose 的句柄
```

节点自身的通用方法（都来自 nebula 的 `Config` / `ConfigItem`）：

```kotlin
cfg.isDefault()        // 是否等于默认值（界面据此禁用"重置"按钮）
cfg.resetDefault()     // 恢复默认值
cfg.getValue()         // 当前值；cfg.setValue(v) 写入
cfg.name / cfg.valueType / cfg.path
```

复杂类型（自己写 `Codec` 的）用 `addConfig(ConfigItem(...))` 建节点：

```kotlin
private val easingCustomConfig =
    addConfig(ConfigItem("easing_custom", CubicBezier.Standard, ConfigSerde.of(CubicBezier)))
```

约定：**需要"写到运行时"的项在 `init()` 与 `observe` 两处都灌一次**（`init` 负责启动即生效，
`observe` 负责运行期改动），仓库里的 `IGConfig` 就是这么写的：

```kotlin
val disableWorldRender by configBoolean("disable_world_render", false)
    .apply { observe { ComposeScreenDefaults.disableWorldRenderByDefault = it.getValue() } }

override fun init() {
    super.init()
    ComposeScreenDefaults.disableWorldRenderByDefault = disableWorldRender
}
```

## 4. 生命周期

注册到处理器后（`register`）由处理器负责：

| 处理器 | 时机 | 行为 |
|---|---|---|
| `ClientModConfigHandler` | `ClientLifecycleEvent.Starting` | 逐个 `manager.init()`（构造配置项树）→ `load()`（读文件）；**读失败会 `forceSave()` 重写** |
| `ClientModConfigHandler` | `ClientLifecycleEvent.OpenGameMenu` | `savable()` 的项异步保存（`asyncSave()`） |
| `ClientModConfigHandler` | `ClientLifecycleEvent.Stopping` | 同步 `save()` |
| `ServerModConfigHandler` | `ServerLifecycleEvent.Starting` | 逐个 `manager.init(server)` → `load()`；同样读失败 `forceSave()` |
| `ServerModConfigHandler` | `ServerLifecycleEvent.Saving` | `savable()` 的项异步保存（`asyncSave()`） |
| `ServerModConfigHandler` | `ServerLifecycleEvent.Stopping` | 同步 `save()` |

`ServerModConfigManager` 多了个 `init(server: MinecraftServer)`：处理器在 `Starting` 时把服务器实例灌进来，
配置文件因此落在**当前存档目录名**下（`configPath = <存档目录名>/<modId>`，相对服务器工作目录）；
`ClientModConfigManager` 用的是加载器的全局配置目录。两者的持久化默认都是 YAML（`yaml()`），
即文件名为 `<name>.yml`。

手动控制（不用处理器或做测试时）：

```kotlin
YourModConfigs.init()        // 初始化配置树（服务端用 init(server)）
YourModConfigs.load()        // 从文件加载（suspend，返回耗时 Duration）
YourModConfigs.save()        // 需要时写回（suspend）
YourModConfigs.forceSave()   // 强制写回（忽略"脏"判断）
YourModConfigs.savable()     // 是否有变更（由节点 notifyChange 置位）
YourModConfigs.asyncSave()   // 异步保存，返回 Deferred<Duration>
YourModConfigs.asyncLoad()   // 异步加载，返回 Deferred<Duration>
```

`ModConfigHandler` 本身也提供 `save()` / `load()`（对全部已注册 manager，suspend）与
`asyncSave()` / `asyncLoad()`（并行执行并取最大耗时）。

## 5. 序列化与文案键

- 复杂类型用 `Codec` 描述：`ConfigSerde.of(CubicBezier)`、`ConfigSerde.of(codec)`，
  或 `addConfig(ConfigItem("key", defaultValue, serde))`。`configList` / `configMap` 的元素（值）类型
  同样可传 `Codec`、`ConfigSerde` 或 `KSerializer`。键值对用 `Codec.pair(codecA, codecB)`。
- 每个配置节点自动得到**翻译键**（`ConfigNode.translationKey`）：根为 `<modid>.config`（管理器名就是
  `config` 时）或 `<modid>.config.<name>`，下面按 `path` 逐级拼接；注释键是同名 + `.comment`
  （`translateCommentKey`）。对应语言文件里写：

```jsonc
"your_mod_id.config.gui.title": "标题",
"your_mod_id.config.gui.title.comment": "显示在界面上的标题",
```

- 节点上另有 `translateText` / `translateComment`（可读可写，写进去就覆盖自动推导的文案）与
  `translateTextWithParent(level, connector)`（带父级路径的拼接展示，快捷键开关的 Toast 用它）。
- 批量导出未翻译的键：`ConfigGroup.exportTranslateKeys(onlyMissing = false, withComment = true)`；
  按文案反查节点用 `ConfigNode.matchWithTranslate(regex)`。

界面（[03 配置界面](03-配置界面.md)）与 tooltip 都按这套键取文案。
